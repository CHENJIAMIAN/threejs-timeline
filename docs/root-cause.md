# 根因分析：天幕消失与整屏惨白

> 记录一次「画面看起来没问题，其实整块材质没编译」的事故。重点不是修了哪一行，
> 而是错误如何在六个层级之间变形、每一层为什么都没能拦住它。

## 一、现象

| 观察 | 时间 | 说明 |
| --- | --- | --- |
| 画面整屏浅灰白，天幕看不出层次 | 2026-10-28 起 | 被当成「纯色天幕」的设计效果 |
| `docs/screenshot.png` 中间一道黑色横带 | 10-28 15:16 | 早期截图，比后续修复更旧 |
| 立柱颜色只有单调浅色 | 持续 | 与色带设计预期不符 |
| 控制台两条 shader 编译错误 | 复现时发现 | 此前无人查看 |

复现方式：加载页面后抓取控制台，得到

```
ERROR: 0:73: 'NaN' : undeclared identifier
ERROR: 0:73: '.0' : syntax error

> 73: DiffuseColor = vec4( ( vec3( ( ( ( NaN.0 * nodeVar1 ) + ( NaN.0 * nodeVar2 ) ) ...
```

## 二、主因果链

```
配置字符串 '#f5f5f7'
  └─ 代码层  parseFloat('f5') → NaN                    ← 根因
       └─ 值层  三个通道全 NaN，三种颜色退化为同一个非法常量
            └─ API 层  TSL float(NaN) 不校验，序列化成 GLSL 字面量 "NaN.0"
                 └─ 标准层  GLSL 无 NaN 字面量 → 切成标识符 NaN + 后缀 .0
                      └─ 编译失败 → program 未链接 → 材质不绘制
                           └─ 渲染层  露出 scene.background 的浅灰白
                                └─ 认知层  「惨白」被读成「设计如此」
```

关键特征：**错误在每一层都变形一次，且没有任何一层抛异常**。从「一个数字没解对」到「看起来像设计」，中间九层全部沉默。这条链可以叫**沉默失败链**——越往下游，症状离原因越远。

## 三、分层溯因

### 语言层：宽容解析

`parseFloat` 遇到非法字符返回 `NaN` 而不是抛错，这是它的设计。要解析十六进制必须用 `parseInt(s, 16)`。用错函数不报错，只产生一个「合法的数字值」。

```js
parseFloat('f5')      // NaN
parseInt('f5', 16)    // 245
```

### 值层：NaN 的传染

`hex()` 被调用三次，每次都在同一处崩，于是 `[NaN, NaN, NaN]`。单点错误被放大成整体退化——不是「某个通道偏色」，而是三种颜色同时失效。

### API 层：序列化不校验

TSL 把 JS number 直接序列化进 GLSL，`float(NaN)` 得到 `NaN.0`。缺两道闸：入参校验，以及拒绝非法常量。

### 标准层：GLSL 词法

GLSL 没有 `NaN` 字面量，`NaN.0` 被切成标识符 `NaN` 和浮点后缀 `.0`，所以**同一语句报两个错**。这是识别此类 bug 的特征信号：两条报错同源，不是两个独立 bug。

### 框架层：失败策略

three 的材质编译失败只打日志，渲染器继续跑，没有 fallback 材质、没有失败计数。框架选择「尽量继续」，代价是把错误藏进画面。

### 渲染层：症状由兜底决定

`main.js` 里有 `scene.background = new THREE.Color(sky.colors.bottom)`。天幕不画，就露出这层背景色——所以视觉症状是「白」，而不是「黑」。**症状由另一个模块的兜底行为决定**，这也是它看起来像设计的原因。

### 环境层：两次编译与后端回退

错误出现两遍（`Shader Error 0` 与 `1282`），对应同一材质在两个上下文各编译一次（环境贴图烘焙 + 主场景）。headless 环境拿不到 WebGPU 适配器，回退 WebGL2，但**两个后端同样失败**——说明问题在 TSL 生成阶段，与后端无关。

顺带一个反面教训：该环境的 11–24fps 是软件渲染数字，**不能当作性能结论**。

### 工程层：验证漂移

截图（15:16）比黑带修复（15:59）更旧，比这次修复更旧。图、代码、结论三者不同步，「看起来没问题」就成了默认判断。再加上静态服务的 304 缓存，修复后第一次复验仍然看到旧错误——**修复和验证之间还隔着缓存这一层**。

## 四、跨层缺陷：契约分裂

同一个颜色字符串，在两个地方被两套解析器处理：

| 位置 | 解析方式 | 结果 |
| --- | --- | --- |
| `scene.background` | `new THREE.Color(str)` | 正确，且做 sRGB→linear |
| 天幕 `colorNode` | 手工 `parseFloat(slice)/255` | `NaN`，且把 sRGB 值当线性用 |

即使把 `NaN` 修掉，第二行仍然偏亮：`#e1e1e8` 的 0.882 被当作线性值，转回 sRGB 约 0.948，亮 17/255。这不是笔误，是**配置边界上没有统一解析层**。

## 五、修复

1. 新增 `src/color.js` 作为颜色解析的唯一入口：
   - `isHexColor()` / `parseHexColor()` 只接受 `#rgb` / `#rrggbb`，非法返回 `null`；
   - `toColor()` 返回线性工作空间颜色，`toLinearRGB()` 给 TSL 常量；
   - 非法输入回退默认色，绝不产生 `NaN`。
2. 天幕改用 `toLinearRGB()`，与 `scene.background` 走同一条路径。
3. `src/config.js` 的 `normalize()` 增加颜色兜底：凡是默认值为 `#...` 的键，非法值一律换回默认。
4. 删除三张过期调试截图，重拍 `docs/screenshot.png`。

## 六、防线

- **冒烟检查** `scripts/smoke.mjs`：shader 报错、未捕获异常、canvas 出图、截图体积（空白画面判失败）。已做负向验证——把 `parseFloat` 版本注入回去，脚本能准确失败并打印报错。
- **截图可复现**：`--reset-view` 固定视角，出图角度不再随机。
- **禁用缓存**：脚本加载页面时 `Network.setCacheDisabled`，避免 304 让修复「看不见」。

## 七、可复用判据

1. 看到 `'NaN' : undeclared identifier`，先找生成代码里的字面量——这是 JS 数值错误在 shader 层的固定指纹，别去 GLSL 里找。
2. 同一语句报两条错（undeclared + syntax），先怀疑同一个非法字面量被拆开。
3. 颜色、尺寸这类「配置字符串」必须在边界统一解析一次，不要在消费点各写一遍。
4. 材质编译失败要可观测：至少计数 + 告警，最好有 fallback 材质。
5. 修复后必须无缓存复验，否则 304 会让你以为没修好。
6. 截图要能追溯到代码版本，否则它是一张会骗人的「证据」。
7. 性能数字必须标注渲染后端，否则结论会跨层错配。
8. 视觉退化和设计意图可能无法区分——需要基准对照（首帧截图 + 报错断言）才能判定。

## 八、尚未覆盖

- 真机 WebGPU 后端下的观感未验证（当前环境只有 WebGL2 回退）。
- 天幕三段颜色是**硬切换**（注释写明刻意为之），不是渐变；如果后续想要柔和过渡，需要另做改动，与本次事故无关。
- 冒烟检查只覆盖「首屏能画、无报错」，不覆盖交互路径（悬停、聚焦、配置面板应用后重载）。
